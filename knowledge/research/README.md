# External research cache

These notes condense prior implementation-bound research and preserve its original versions, dates, and primary sources. Every note records its fetch date and a TTL near the top.

Before using any claim in implementation:

1. Compare the researched version with the project's lockfile, the Docker/runtime pin, and the target database or service version where relevant.
2. Check the original fetch date and TTL.
3. Re-read installed source for version-specific behavior and refresh stale external documentation through the research specialist.
4. Verify project precedents in the active branch.

The notes are available to both runtimes only when opened explicitly. They are not an automatic cache injection. The research specialist is cache-first here and propose-only; the main thread or an explicitly assigned writer applies new or refreshed notes.
