# Worktree and shared-checkout dispatch paths

- A subagent shares the repository filesystem but may begin with a working directory different from the one intended by the parent. In worktree sessions, put the absolute worktree root and owned paths in every write brief, and state "do not resolve paths relative to your working directory".
- Tell writers that other agents and the user may have live changes. They must preserve unrelated edits and must not use broad restore, reset, checkout, or stash operations (`git restore`, `git reset`, `git checkout --`, `git stash` in any form). A scoped `git stash push -- <file>` still reverts that file's whole uncommitted diff; prescribe edit-based disable/restore for red checks instead.
- Before dispatching a writer, record status for the intended checkout and any adjacent checkout that could be confused with it (plus a diff of any already-dirty file the writer could touch). Afterward, compare both states and inspect every owned file directly.
- In the Claude runtime, an optional PreToolUse hook (`.claude/hooks/git-guard.sh`), when installed, enforces the ban on stash (except the read-only `list`/`show`), restore, reset, destructive checkout, `clean -f`, force switches, autostash (`--autostash` or a true `rebase`/`merge.autoStash` config) and `worktree remove --force`, including when run through python/node/perl/ruby exec calls. Codex has no such hook, so this rule is its only guard. Treat any of these commands in a brief as a defect.
- A missing worktree-only file is a strong wrong-directory signal. Pause that edit, resolve the correct root, and verify neither checkout was changed unexpectedly.
- The wrong-directory hazard also occurs in single-checkout sessions: a writer whose targets sit under a nested folder can create a stray nested `.claude/` or other runtime directory there. Treat any such untracked directory below the repo root as a wrong-directory write; move needed content to its owned location and delete the stray tree. Writers never create per-agent memory directories.
- When writers run concurrently on disjoint files but share factual dependencies, recheck those facts immediately before reporting. Disjoint write ownership does not make cross-file claims stable.
- If a write lands in the wrong checkout, preserve both trees and move only the exact hunks after inspecting them (export a patch, apply it in the correct tree, reverse exactly those hunks in the wrong one). Avoid whole-file restoration that could discard unrelated work.

This rule applies whenever a task uses a worktree or more than one checkout, and whenever a dispatch brief uses absolute paths to distinguish shared working directories.
