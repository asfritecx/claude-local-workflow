# Writer briefs: digest crib files first

- Never point a writer agent (code-developer) at a multi-thousand-line crib/reference file with "read only the targeted regions" instructions — the instruction does not bound reading. Observed in practice: a writer spent its whole budget reading two multi-thousand-line cribs and died with ZERO writes.
- Extract the recipe FIRST with a code-digester (or a warm reader that already holds the file) and paste the distilled digest into the writer brief; the writer should only need to read its own target files.
- The digest pass also catches brief errors: observed in practice, a recipe digest corrected a wrong function arity in the orchestrator's own brief before the replacement writer ran.
- A `path:line` back-reference INTO the same document the writer is being told to edit self-invalidates the moment the writer inserts content above that line. Observed in practice: a brief cited a rule by line number, the writer's own mandated insertion pushed that rule twenty lines down, so the citation was already wrong by the time the edit landed — and a corrected number would itself re-stale at the next insertion. Re-derive such a citation AFTER the insertion, or omit the line number and cite the document by name.
- **Anchor a writer brief by VERBATIM TEXT, never by line number, for any file the writer will itself edit.** Observed in practice, twice in one run: a plan cited line numbers that an earlier insert in the same run had already shifted, and the writer brief then cited a line that the writer's own insertion moved. Line numbers stay safe only for files the writer reads and does not modify.
- **A brief that changes a public function's signature, parameters, or return type MUST quote the plan's declared interface block VERBATIM into the brief — never paraphrase it from the surrounding prose.** Observed in practice: most of one review's confirmed findings were interface deviations with this single root cause. The orchestrator read a prose sentence — "retain their external signatures, defaults, and return container shapes" — treated it as freezing the whole contract, and never read the `## Interfaces` fenced block above it. Consequences: a parameter was ADDED to a signature the plan had frozen, and a field the plan explicitly DECLARED on the returned type was never added at all — the reader selected the column and then discarded it, so the deviation was invisible in the query. The trap is precise: "return **container** shapes" freezes `Record<string, T[]>`, it does NOT freeze `T`'s member fields. **If a plan has an `## Interfaces` block, that block is the contract; the prose around it is commentary.** Paste the fenced block into the brief and require the writer to diff its shipped signature against it.
- General decomposition: readers distill context, writers receive digests, and the orchestrator verifies the tree directly — writer claims are never relayed unverified.
